2. 为什么 2D（不是失败，是正确选择）

硬件现实

  • 240×320 SPI LCD，无 GPU
  • PSRAM 约 8 MB，WiFi/LVGL/栈还要占
  • 实时骨骼网格渲染不可行
  • Lottie（Rlottie）在 lv_conf.h 里已关闭

2D 精灵的优势

  • 帧率稳定、功耗可预测
  • 换素材 = 换脸，不必动核心逻辑
  • 可用 AI / 3D 工具离线生产，表上只播放
  • 业界 MCU 表、Tamagotchi 类设备均走此路
3D 的角色 保留为可选制作工具：在浏览器里调 pose、预览横竖屏，再烘焙成 2D 帧。 也可以完全不用 3D，直接用 AI 或手绘工具出 sprite sheet。

3. 三层模型：状态 / 表情 / 动作

不要把「交互状态」和「视觉表情」混成一个字段。

Layer 1 · 交互状态 (emotion)     ← 设备/客户端 FSM 驱动，LLM 不参与
  idle → listen → think → speak → idle

Layer 2 · 表情 (expression)       ← LLM 在 speak 阶段决定
  neutral / happy / shy / surprised / sad

Layer 3 · 动作 (action)           ← LLM 从有限目录里选
  wave / nod / bounce / still / peek …
层谁决定何时切换例
emotion客户端 FSMtap 后立刻 listen；等 API 时 thinklisten
expressionLLM 结构化输出API 返回 speak 时happy
actionLLM 结构化输出同上，映射到 clipwave

8 个 emotion 枚举已在 firmware/include/ui.h、Flutter、Web 三端对齐。expression / action 是二期扩展字段，不影响现有 API 兼容。

5. 素材管线（含 AI 工具）

目标：产出统一规格的 PNG 序列 → pack_lumi_frames.py → 固件二进制。固件格式不变，只换内容。

5a. 现有管线（3D 烘焙，可选）

lumi.glb（Blender / Mixamo / USDZ 转 GLB）
  → cloud/static/watch/bake.js（Three.js 离屏渲染）
  → PNG 序列（160×176）
  → scripts/pack_lumi_frames.py
  → firmware/src/lumi_frames.rgb565 + include/lumi_frames.h

GLB 不进 Git；scripts/usd_to_glb.py 可从 USDZ 转换。Web 预览用 elf3d.js 调 pose 后再烘。

5b. 纯 2D / AI 生成（推荐探索方向）

工具类型举例产出注意
AI 视频 → 抽帧 Runway Gen-3、Pika、Kling、可灵 MP4 → ffmpeg 抽帧 → 抠图/缩放 需统一背景色、角色大小；人工筛帧去闪烁
AI 图生图 + 手动补帧 Midjourney、Stable Diffusion、Flux 关键 pose 各一张 → Aseprite 补中间帧 适合表情变化少的 idle / think
2D 骨骼 → 导出序列帧 Spine、DragonBones、Live2D Cubism 直接导出 PNG sprite sheet 表端不跑骨骼，只烘焙帧；制作效率最高
像素 / 逐帧手绘 Aseprite、Procreate、PixelOver PNG 序列 风格最统一；适合小角色 160×176
Lottie → 烘焙 After Effects + Bodymovin 浏览器渲染后截图（类似 bake.js） 设备不跑 Lottie，但可以当制作工具

5c. 素材验收 checklist

  • 背景色与表盘主页一致（当前 #102a44 或透明底）
  • 角色在 160×176 框内居中，脚不裁切
  • 循环点首尾 pose 接近（loop 无跳变）
  • 帧数 8–16，文件总大小单 clip < 900 KB
  • 经 pack_lumi_frames.py 打包后在 Web 预览 GIF 检查

5d. 多 clip 打包（规划中）

lumi_frames.rgb565          ← 所有 clip 顺序拼接
lumi_frames.h               ← clip 目录表

struct LumiClip {
  uint16_t offset;    // 起始帧 index
  uint8_t  count;     // 帧数
  uint16_t interval;  // ms / 帧
  bool     loop;
};

换素材时只替换 .rgb565 和头文件里的 offset 表；若 clip 数量不变，固件逻辑可不动。

6. AI 怎么驱动表情

原则 FSM 状态（listen / think）由客户端本地切；LLM 只在 speak 阶段决定「什么表情 + 什么动作」。 AI 只能从预定义目录里选，不能自由发明动画名。

6a. 云端 API 扩展（规划）

POST /v1/sessions/{id}/turn 返回值在现有字段上扩展：

{
  "emotion": "speak",
  "expression": "happy",
  "action": "wave",
  "text": "嘿嘿，你好呀！",
  "subtitle": "嘿嘿，你好呀！"
}

MQTT dn/meta 同步带上 expression 和 action。旧客户端忽略新字段，仍按 emotion 工作。

6b. LLM 提示词（规划）

回复格式必须是 JSON：
{"reply":"...", "expression":"happy|shy|surprised|sad|neutral", "action":"wave|nod|bounce|still"}
expression 和 action 只能从上述选项里选。

6c. 一次对话的时序

用户 tap
  ├─ 本地: emotion=listen,  clip=LISTEN_LEAN
  ├─ 上传 text/audio
  ├─ 本地: emotion=think,   clip=THINK_BLINK
  │
  ├─ API 返回: emotion=speak, expression=happy, action=wave
  ├─ 本地: clip=SPEAK_HAPPY_WAVE, 播字幕
  ├─ (未来) TTS 到达 → 嘴型帧跟 RMS
  │
  └─ 2.2s 后: emotion=idle, clip=IDLE_WAVE

6d. 动作目录（建议起步 6 个）

action用于对应 clip
stillquiet / 短回复IDLE_BREATHE
wavehappy speak / 打招呼SPEAK_HAPPY_WAVE
nodlisten / 表示在听LISTEN_NOD
bounceexcited / alarmALARM_BOUNCE
tiltthink / 歪头想THINK_TILT
peekshy / 害羞SPEAK_SHY_PEEK

7. 固件侧（最小改动原则）

换 2D 素材 ≠ 换固件 若 clip 数量和切换规则不变，只替换 lumi_frames.rgb565 即可。 固件改动仅在需要「按 emotion / expression 切 clip」时做。
改动文件必要性
clip 播放器（offset + loop）firmware/src/bw_ui.cpp多 clip 时必须
clip 目录表firmware/include/lumi_frames.h多 clip 时必须
emotion → clip 映射bw_ui.cpp 或 ui.cpp按表情切换时必须
仅换帧内容lumi_frames.rgb565素材迭代，随时可换
Legacy GFX 路径firmware/src/ui.cppBW_USE_LVGL=0 时仍可用；不优先维护

当前 gap：bwUiShowHome(subtitle, faceHex) 里 faceHex 被忽略，sprite 不随 emotion 切换。这是下一步固件最小增量。
