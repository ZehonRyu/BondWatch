1. 产品定位（软件视角）

它是什么

手腕上的 AI 伴侣终端：眼睛（表情/字幕）+ 嘴巴（听/说），大脑在云端。

不是运动表，不是应用商店生态表，不做完整 watchOS。

软件边界

  • 表端 FreeRTOS：显示、触摸、键、闹钟、勿扰、网络收发
  • 手机 Flutter：绑定、管理、假手表、长聊放大
  • 云 Python：ASR / LLM / TTS / 记忆 / 情绪标签

2. 软件架构（FreeRTOS）

ESP32 Arduino/IDF 底层已是 FreeRTOS。推荐任务划分（可渐进落地）：

任务优先级职责注意
ui_task 高 组帧、局部刷新、页面状态机 禁止在 UI 里阻塞读麦/网络
input_task 高 触摸手势、实体键去抖 输出统一 Gesture 事件队列
audio_task 中（二期） I2S 采播、VAD 可选 默认关闭；按需 start/stop
net_task 中（二期） Wi‑Fi / 4G、会话 API 断网降级：闹钟/勿扰/提示脸
persist_task 低 NVS 亮度/语言/触摸映射 不存长期记忆正文
UI 技术选型建议 现阶段：Adafruit GFX + U8g2 中文（已跑通）。
界面继续加深时：迁 LVGL on FreeRTOS（业界 MCU 表常见，动画/列表更高级，仍开源）。 不要为「看起来像智能表」去换 Wear OS 模组，除非产品形态改成买现成表芯。

5. 手势与按键语言（已冻结 · Model B）

用户只记三件事 点一下脸 = 说话（一期仅提示「语音已关」）· 下滑 = 控制中心 · 上滑 = 应用。左右滑 / 双击息屏 / 长按勿扰已取消。息屏靠电源键或控制中心「锁屏」；2 分钟主页无操作自动息屏。
输入主页子页对话中（二期）
点一下一期：轻提示；二期：对讲激活控件打断
下滑控制中心回主页忽略
上滑应用墙设置列表滚动忽略
左右滑 / 双击 / 长按无无无
电源短按亮/灭同左同左
音量短按循环音量同左同左
音量长按打开设置同左同左

应用墙：主页 / 时钟 / 闹钟 / 秒表 / 声音 / 设置。控制中心含勿扰、手电、亮度、音量、锁屏、进应用。

6. 怎样把 UI 做高级（FreeRTOS 可行）

1. 少即是多

主页禁止仪表盘：不要 WiFi/4G/亮度一排图标抢脸。状态最多一行，伴侣脸占视觉中心。

2. 零闪烁

禁止每次点击 fillScreen。局部脏矩形；列表/音量/控制中心已验证这条路。

3. 动效克制

MCU 上「高级」= 短促过渡（8–12 帧滑入）+ 眨眼偶发，而不是每帧挥手重绘。

4. 中文排版

标题/正文两级字号；hint 用次要色；避免英文残留。语言设置全局 tr()。

5. 情绪叙事

高级感来自「它像活的」：听/想/说/勿扰/没网各有脸与一句人话，而不是 Technical Error。

6. 触感对齐

触摸映射可校准；热区大于视觉按钮；左右加减与坐标一致（已踩过坑）。

元素建议

7. 怎样把整体做得最好

  1. 双轨 UI：交互与文案先在 bondwatch-sim.html / Flutter 假手表定稿，每周只向固件合入「已冻结」页。
  2. 表情库优先于皮肤：先做出 6–8 种可读情绪脸，比换主题更赚「高级感」。
  3. 二期语音要「半双工礼貌」：它说时你点按才打断；默认不开常听，建立信任。
  4. 云端人格资产：人设、记忆、场合白名单放云端；表端只缓存闹钟/勿扰/亮度。
  5. 演示脚本：准备 60 秒演示——亮屏脸 → 控制中心勿扰 → 闹钟 →（二期）一轮对话表情对得上。
  6. 何时上 LVGL：当设置超过一屏、需要滑列表惯性/开关组件时再迁；现在不必为迁而迁。
